## 4. 仍需按场景验收的边界

| 项目 | 当前边界 | 验收重点 |
| --- | --- | --- |
| 真实 Youli/MCN 登录与公司切换 | 文件身份按 Octop 账号，不按 `company_id` | 员工身份绑定、机构切换、到期状态、连接器凭证和业务租户检查 |
| 真实 MCN 工具及异步导出 | 返回任务 ID 不代表生成成功；列表分页会影响任务发现 | 同账号多任务、跨账号/公司拒绝、任务失败/超时、下载结果与发起任务一致 |
| 网页终端与本地 MCP | 已有低权限适配，不代表所有运行依赖都兼容 | 实际程序、技能、认证目录、环境变量、重连身份及异常清理 |
| 宿主或容器公开资源 | UID 方案仍允许访问权限开放的宿主文件和网络 | 部署文件权限、敏感挂载、网络可达性和实际宿主策略 |
| 总资源占用 | rlimit 不等于 CPU/内存 cgroup 或用户总磁盘配额 | 目标并发量、累计文件、进程、内存和磁盘边界 |
| 旧业务数据 | 保留原目录并复制有范围限制 | 真实历史目录、外部挂载、较大文件、共享历史归属及回滚后内容导出 |
| 插件、设备及团队能力 | 部分入口拒绝或禁用 | 需要这些能力时单独适配，不能通过恢复 root 执行绕开限制 |
| bubblewrap 叠加 | 没有组合实现和运行证据 | 仅在新增沙箱目标明确后验证 user namespace、路径、全部启动入口和失败拒绝 |
| 新增启动维护策略 | 整理期间外部改动，仅核对部分源码 | `strict/repair` 成功与失败、ACL/owner 修复日志、健康与就绪区别、管理员诊断及全部执行入口关闭 |

## 5. 本轮文档检查及复核方式

本轮写入仅限 `docs/change-records/` 下的 Markdown 文件。交付前检查目录内相对链接的本地目标、代码围栏、Mermaid 兼容写法、文件末尾及行末空白，并对比文档新增前后的业务代码 diff 与原工作区状态。

本轮对 4 份 Markdown 的本地链接、代码围栏、Mermaid 兼容写法、UTF-8、作者署名及空白执行文档检查。工作区对比发现外部并行新增/修改了启动维护相关业务文件，因此不能声明整个业务 diff 保持不变；这些变化已单独记录，本轮未写入其源码。文档检查通过不能提升业务功能的运行验证状态。

可在 Octop 仓库中只读查看：

```powershell
git status --short
git diff --check HEAD
git diff --stat HEAD
git ls-files --others --exclude-standard -- docs/change-records
```

新文件尚未加入索引时，普通 `git diff HEAD` 不展示其正文；需要直接读取本目录文件，不能以空 diff 宣称文档已经检查。

复查时从 [变更范围](01-变更范围与原因.md) 找到实际实现，再对照本页证据范围。只有本次场景的运行验证完成，才能将相应功能结论从静态确认提升为已验证。
